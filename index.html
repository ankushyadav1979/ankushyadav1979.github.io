Strategy Research & Execution Framework

AlphaGrep Securities, core team framework

The base layer that mid-frequency trading strategies are built on, where the same strategy code runs in backtests and in live trading.

Proprietary — code not public
Problem
When research backtests and production run on different code, results diverge the moment a strategy goes live. Every strategy also has to deal with the same hard details: lot sizes, expiries, corporate actions, costs, margin and restarts.
Approach
Strategies subclass one event-driven base class (day start, bar updates across multiple bar sizes, fills, day end) and only express target positions and price limits. In a backtest, the framework replays stored market data and writes timestamped target files, with configurable latency, for an execution simulator. Live, it reads bars from the database, writes targets for execution, and saves its state so it can restart safely. Per-instrument accounting covers P&L, commissions, slippage models, dividends, currency conversion and inverse contracts. The framework closes expired contracts, applies splits, bonuses and name changes, and respects trading hours for each symbol. It tracks exchange margin and stress-tests the book under 8 spot and volatility shock scenarios of up to ±15%. For options, it computes Greeks and attributes P&L to them, builds synthetic futures from call–put pairs chosen within a delta band (rolling to new strikes when delta drifts), and nets offsetting legs of multi-leg positions. Runs report net P&L, Sharpe, day-win rate, maximum drawdown and recovery time, P&L per turnover in basis points, and intraday versus overnight splits by year and product type. A launcher runs end-to-end live tests with a state-machine test strategy.
Technologies
  • Python
  • pandas
  • NumPy
  • MySQL
  • Black–Scholes
  • pyfolio
Results
One codebase from research to production: a strategy that passes its backtest runs live unchanged, with P&L, costs, margin and risk measured the same way in both.

Options Greeks & Implied Volatility

Built at AlphaGrep Securities

Daily delta, gamma, theta, vega and implied volatility for every listed option across Indian, US and CME markets.

Proprietary — code not public
Problem
Traders and researchers needed a consistent, daily view of implied volatility and risk across thousands of option contracts on NSE, BSE, US equity and index options (including SPX, NDX and RUT) and CME E-mini S&P options, each with its own symbology, sessions and time zones.
Approach
Joins exchange reference data, quotes and bars for the whole option chain, then prices each contract from the average mid-quote over the first 15 minutes of trading against the underlying’s open. Time to expiry is computed to the second across exchange time zones, with the risk-free rate taken from a dated rate series, and implied volatility is solved numerically before computing the Greeks. A daily report ranks the top 20 underlyings by options turnover with their at-the-money IV and cross-checks turnover and volume against an independent market data source, flagging mismatches.
Technologies
  • Python
  • pandas
  • NumPy
  • Black–Scholes
  • Linux
Results
A daily Greeks and IV dataset for the full option chain on four markets, plus an automated top-turnover report with built-in validation, posted to trading channels on Slack.

Stats Generator

Built at AlphaGrep Securities

A plug-in framework that computes daily liquidity, volatility, spread and options statistics for every instrument a strategy might trade.

Proprietary — code not public
Problem
To choose and size instruments, strategy research needs the same daily statistics for everything from Indian index futures and options to US equities, KRX and crypto perpetuals. Each market has its own sessions, holidays and contract details, and these numbers were being worked out one market at a time.
Approach
It runs in two stages from a per-exchange JSON config. The first stage pulls 1-minute bars and quotes through the ingestion tool and splits them into per-underlying files for futures, spot and options. The second stage runs a set of indicator plug-ins. Each plug-in declares the data it reads, whether it runs per minute or per day, and how many trading days of history it needs, counted using exchange holiday calendars. Indicators include minute-level implied volatility and Greeks (Black–Scholes); 1-day and 5-day average notional traded (using volume for inverse contracts); volatility of 5-minute and 4-hour returns averaged over 5–10 days, optionally adjusted for overnight gaps and filtered for bad price jumps; average 15-minute volume; and bid-ask spread divided by return volatility, as a measure of trading cost. For Binance and FTX, the list of instruments is built automatically each day from reference data covering every perpetual and USDT spot pair. A scheduled script runs everything for the previous trading day, and a companion script turns strategy P&L, net of slippage, into a pyfolio tear sheet against a benchmark such as NIFTY 50.
Technologies
  • Python
  • pandas
  • NumPy
  • Black–Scholes
  • pyfolio
  • Bash
Results
A daily, date-partitioned library of statistics across NSE, KRX, US equities and hundreds of crypto perpetuals on Binance and FTX, where a new indicator is one class and a new market is one config file.

Market Data Ingestion Tool

Built at AlphaGrep Securities

One config-driven tool that turns market data from many exchanges into a single, research-ready format.

Proprietary — code not public
Problem
Researchers needed historical bars and quotes for futures, option chains, equities, index spots, crypto perpetuals and FX from many exchanges, including NSE, BSE, US, CME, KRX, Binance and China. Every source had its own symbology, headers, sessions and holiday calendar, so each new market meant another one-off loader.
Approach
A single JSON config lists the exchanges, instruments, option strike ranges and data types to fetch, such as bars, quotes, open interest, trades and funding rates. The tool pulls data through the in-house market data service (which draws on vendors such as Refinitiv and Tardis) or parses raw Algoseek option files, then maps every source onto one bar schema and stores it by ticker and day as zstd-compressed pickles. Each file has matching product and commission info: tick size, multipliers, expiry and strike. It handles most-liquid contract selection and rollovers, holiday calendars, 24/7 crypto markets, half days and overnight sessions. It tracks what has already been downloaded, so a rerun only fetches missing dates or new strikes. It works in daily batches to keep memory bounded, runs in parallel across processes, stops if a source’s schema changes, and reports each run on Slack.
Technologies
  • Python
  • pandas
  • multiprocessing
  • zstd
  • MySQL
  • Slack API
Results
One consistent, date-partitioned dataset across exchanges and asset classes, where adding a market or extending history is a config change and an incremental rerun.

Sanity Tool

Built at AlphaGrep Securities

Daily checks that market data was actually downloaded, and that what was downloaded is usable.

Proprietary — code not public
Problem
A missing file or a day of empty bars in the research dataset breaks backtests quietly, and usually isn’t noticed until someone’s results look wrong.
Approach
Two checks run after each download. The completeness check confirms a data file exists for every ticker in the config at each bar frequency, compressed or not, handling each exchange’s naming rules. The correctness check opens every file, joins it to its product info, keeps only bars inside that exchange’s trading session (NSE/BSE, KRX, MCX, US, or near 24-hour for crypto), and confirms each option expiry has at least one complete OHLC bar, with stricter all-field checks for NSE equities. Weekends and exchange holidays are skipped. Failures go into a running JSON re-download list by symbol, frequency, date and expiry, which clears itself once the data is fixed, and stale product info for missing files can be removed so the re-download starts clean.
Technologies
  • Python
  • pandas
  • zstd
  • JSON
  • Slack API
Results
Missing or broken market data is caught the same day with an exact list of what to re-download, posted to Slack with the full log attached.

Position Reconciliation System

Built at AlphaGrep Securities

Nightly and on-demand checks that the positions in the trading database match what is actually open at the exchange.

Proprietary — code not public
Problem
Positions recorded in the trading database can drift from the positions open at the exchange, and expired or rolled contracts cause false breaks. Every real break has to be found and fixed before the next session.
Approach
Pulls overnight open positions from exchange drop-copy and order-routing logs over SSH and compares them with the MySQL positions, P&L-tracking and target-position tables, symbol by symbol, across NSE, BSE, CME, US, KRX and CFFEX. Expired contracts are filtered out using each exchange’s reference data and symbology (CME month codes, NSE encoded expiries, BSE series), and each mismatch is written out as a ready-to-apply correction record.

  • MySQL
  • pandas
  • Paramiko / SSH
  • Slack API
Results
29% fewer expired-symbol errors and 37% faster data processing, with a per-account report on Slack every day.

Nurse Scheduling System

Full-stack project, 2026

A web app that matches patient care requests to available nurses with the right skills, and manages shifts end to end.

Backend on GitHubFrontend on GitHub
Problem
Assigning nurses to patient requests by hand is slow and error-prone: every visit needs a nurse who is free and has all the required skills (ICU, ER and so on), and stale requests and finished shifts have to be cleaned up.
Approach
